Harness Engineering

从 Prompt / Context 到 Agent Runtime 的工程转向

工程师的角色从"代码编写者"变为"智能体驾驭者"

分享人

Why Now

为什么后端工程师开始关心 Harness

01 · 生产环境 Agent 化

智能体不再是玩具，而是要和真实服务、数据库、代码库集成的第一类公民。

02 · 可靠性要求变高

可观测性、回滚、限流、权限控制……这些后端痛点现在也是智能体的痛点。

03 · Prompt 不够用了

我们需要更结构化的方式来约束、观测、反馈一个智能体的行为。

04 · 知识与工具管理

Wiki、Profile、Skill、Working Memory 需要被当作工程资源来管理。

Evolution

Prompt → Context → Harness

Prompt

  • 静态文本模板
  • 单次交互
  • 无状态
  • 难以调试

Context

  • RAG + 对话历史
  • 有状态会话
  • Memory 是黑盒
  • 缺少反馈闭环

Harness

  • 结构化环境 + 约束
  • 可观测、可回滚
  • 显式 Memory 分层
  • 自动化反馈闭环

Components

Harness 的五个核心组成

环境

沙箱、文件系统、网络策略、权限边界——Agent 运行在什么地方。

工具

API、函数调用、数据库查询——Agent 能做什么操作。

知识

Wiki、文档、代码索引——Agent 知道什么。

反馈

人工标注、自动评测、奖励信号——Agent 怎么变好。

约束

Token 预算、超时、重试策略、安全策略——Agent 不能做什么。

Runtime

Runtime Substrate：从 Thread 到 App Server

核心概念

  • Thread：会话的容器
  • Turn：一次交互轮次（用户 → Agent → 用户）
  • Item：单条消息/事件/工具调用

App Server

  • 持久化 Thread / Turn / Item
  • 调度与并发控制
  • 可观测性与事件流

Mapping

各组件在 Harness 里的位置

Resource / Wiki

长期知识 · 只读 · 版本化

Profile / Memory

用户/Agent 状态 · 持久化

Skill

可复用工具集 · 注册发现

Working Memory

短时上下文 · 随 Thread 销毁

Feedback Loop

生产 Harness ↔ 评测 Harness

生产 Harness

  • 真实用户流量
  • 真实工具调用
  • 收集行为日志
  • 用户反馈信号

评测 Harness

  • 回放生产用例
  • 模拟工具调用
  • 自动化评测
  • 回归测试

双向反馈闭环

Minimal Viable

Python / TypeScript + Postgres / Docker 下的最小落地

存储层 (Postgres)

  • thread 表（会话）
  • turn 表（轮次）
  • item 表（消息/事件）
  • profile 表（用户/Agent 状态）

运行层 (Docker)

  • App Server (FastAPI / Express)
  • Agent Worker 进程
  • 工具沙箱容器
  • 事件总线 (Redis)

Myths

最容易误解的 5 个点

误解 1

Harness = 提示词工程 → 不，提示词只是很小一部分

误解 2

Memory 越大越好 → 不，分层才是关键

误解 3

所有东西都要 RAG → 不，结构化知识往往更可靠

误解 4

Agent 应该越通用越好 → 不，约束带来可靠性

误解 5

评测就是算准确率 → 不，评测本身就是系统的一部分

Practice

从 0 到 1 搭建 Harness 的步骤

  1. 先搭 Runtime：Thread / Turn / Item 的存储和 API
  2. 加约束层：Token 预算、超时、重试、安全检查
  3. 接工具层：函数调用、数据库操作封装成 Skill
  4. 加知识层：Resource / Wiki 接入，显式 Working Memory
  5. 建反馈闭环：从生产到评测，自动化回归

Future

Harness 工程的下一步是什么？

1. 更细粒度的可观测性

Token 流、工具调用链、Memory 变更的全链路追踪

2. 更自动化的评测

基于生产数据的自动评测、自动调优

3. 更强的约束系统

形式化验证、安全沙箱、权限最小化

4. 更好的开发体验

热重载、调试工具、本地模拟环境
