// why care

为什么后端工程师
开始关心 Harness?

📌 Prompt 不够

只靠指令，Agent 做不了复杂任务——没有环境、没有工具、没有记忆。

📌 Context 不够

只给背景信息，Agent 还是会不可控——没有反馈回路、没有约束、没有恢复机制。

📌 后端需要工程化

我们需要的不是「更聪明的 Prompt」，而是可控、可观测、可恢复的 runtime。

第一页：为什么我们要关心这件事？

因为 Prompt 不够——你光告诉 Agent「去帮我做这件事」，它没有工具、没有环境、没有记忆，做不了复杂任务。

Context 也不够——你把一堆背景信息塞给它，它还是可能跑偏、出错、死循环，而且你没法控制。

对后端工程师来说，我们需要的不是「更聪明的 Prompt」，而是一个能把环境、工具、知识、反馈、约束都管起来的工程化系统。这就是 Harness。

第二页：这三个阶段到底有什么本质区别？

Prompt Engineering 是「告诉 AI 怎么做」——你把步骤拆得很细，让它一步一步来。

Context Engineering 是「给 AI 足够背景」——你把相关文档、历史对话都塞进去，让它理解上下文。

Harness Engineering 是「告诉 AI 目标，让它自己想办法，而且要可控」——你给它环境、工具、反馈回路，让它自己探索，但你同时设置边界、监控状态、出错时能恢复。

这个「可控」是关键——后端工程师要的从来不是「最聪明」，而是「出了问题我能兜底」。

// harness components

Harness 的五个组成部分

①
环境 Environment

Agent 运行的真实世界——文件系统、数据库、API、容器。

②
工具 Tools

Agent 能调用的能力——shell 执行、函数调用、数据读写。

③
知识 Knowledge

Agent 能访问的静态信息——Wiki、文档、知识库。

④
反馈 Feedback

Agent 能收到的信号——成功/失败、用户确认、观察结果。

⑤
约束 Constraints

Agent 不能突破的边界——权限控制、资源限制、安全护栏。

核心公式

Harness =
Environment + Tools + Knowledge + Feedback + Constraints

第三页：Harness 具体由哪几部分组成？

环境 Environment——Agent 不是在真空里运行，它需要文件系统、数据库、API、容器这些真实的东西。

工具 Tools——Agent 需要能调用 shell、执行函数、读写数据。

知识 Knowledge——Agent 需要能查 Wiki、读文档、访问知识库。

反馈 Feedback——Agent 做了一件事之后，要能知道成功还是失败，用户有没有确认，环境发生了什么变化。

约束 Constraints——Agent 不能为所欲为，它有权限控制、资源限制、安全护栏。

这五部分加起来，就是 Harness。

// runtime substrate

Runtime Substrate:
Thread / Turn / Item / App Server

Thread

一次完整的对话任务——从开始到结束，有明确的目标。

Turn

Thread 中的一次交互——用户输入 → Agent 思考 → 行动 → 观察 → 响应。

Item

Turn 中的一个原子操作——一次工具调用、一次记忆读写、一次推理。

App Server

承载这一切的服务——状态管理、事件流、持久化、监控。

第四页：Runtime Substrate 是什么？

Thread——一次完整的对话任务，有明确的目标。

Turn——Thread 中的一次交互：用户输入、Agent 思考、行动、观察、响应。

Item——Turn 中的原子操作：一次工具调用、一次记忆读写、一次推理。

App Server——承载这一切的服务：状态管理、事件流、持久化、监控。

// memory layer

Resource / Wiki / Profile / Memory / Skill 的位置

Resource / Wiki

静态知识，检索增强（RAG）——文档、知识库、FAQ。

Profile / Memory

用户状态、历史对话、偏好设置——持久化在 DB 中。

Skill

可复用能力——工具链、工作流模板、Prompt 模板。

Working Memory

当前 Thread 的临时状态——Context window 内。

架构分层

User Interface
Harness (Environment/Tools/Constraints)
Runtime (Thread/Turn/Item)
Memory Layer (Profile/Wiki/Resource/Skill)
Persistence (DB/Docker)

第五页：大家最关心的——这些 Memory / Wiki / Skill 都放哪？

Resource / Wiki——静态知识，RAG 检索。

Profile / Memory——用户状态、历史对话，持久化在 DB。

Skill——可复用能力：工具链、工作流模板、Prompt 模板。

Working Memory——当前 Thread 的临时状态，在 Context window 内。

评测环境

第六页：生产 Harness 和评测 Harness 的关系？

生产环境——真实环境、真实用户、安全约束严格、有监控告警。

评测环境——隔离 sandbox、模拟用户、可重复测试、指标收集。

核心相同：都要把环境、证据、执行路径和反馈回路结构化出来。

// misconceptions

最容易误解的 5 个点

01
Harness 不是 Prompt Engineering 的新名字

它包含环境、工具、反馈回路，远超 Prompt 的范畴。

02
Harness 不是只有 OpenAI 有

这是一个通用范式，任何 LLM 应用都可以用。

03
Harness 不是只能用 Agent SDK

你可以自己实现 Thread/Turn/Item 模型。

04
Harness 不是只有生产用

评测、测试也都需要 Harness 结构。

05
Harness 不是让 Agent 更聪明

它是让 Agent 更可控、可观测、可恢复。
