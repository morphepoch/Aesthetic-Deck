Harness Engineering
从 Prompt / Context 到 Agent Runtime

为什么后端工程师突然开始关心智能体框架？

@周启明后端全栈 · 15min分享
#Harness #Agent #Runtime

大家好，我是周启明。今天想跟大家聊一个最近我一直在思考的话题——为什么我们这些写后端的，突然开始关心智能体框架了？

今天15分钟，我想给你讲清楚：Prompt、Context、Harness，这三个东西到底为什么是三种完全不同的工程范式。

// part 01 · evolution

三个阶段，
三次范式转移。

Prompt Engineering

告诉模型怎么做。Zero-shot、Few-shot、CoT。

2020-2022

Context Engineering

告诉模型背景是什么。RAG、长上下文、记忆。

2022-2024

Harness Engineering

告诉模型目标是什么，然后让它自己想办法。

2024-至今

好，先看这张图——三个阶段，三次范式转移。

第一个阶段，2020-2022年，Prompt Engineering。核心是告诉模型怎么做。问题在于，你得把每一步都想清楚，模型只是执行。

第二个阶段，Context Engineering。核心是把正确的信息在正确的时间放进上下文。但模型还是不会自己做决定。

第三个阶段，Harness Engineering。核心变了——告诉模型目标是什么，然后让它自己想办法。

// part 02 · what's in a harness

Harness 有五个核心组件。

①
Environment

给Agent一个可感知、可交互的工作环境。

②
Tools

一组可用的API、函数、命令，Agent能主动调用。

③
Knowledge

长期知识库，不是临时塞进上下文的片段。

④
Feedback

观察结果 → 调整策略 → 再尝试的闭环。

⑤
Constraints

边界条件：不能做什么、必须遵守什么。

不是大Prompt

你可以把Harness理解成一个 Runtime + Operating System，而不是一个巨大的Prompt。

它关心的是：如何在可控、可观测、可恢复的前提下，让Agent自主完成复杂任务。

好，现在看Harness的五个核心组件：Environment、Tools、Knowledge、Feedback、Constraints。

这里我想强调一句：Harness不是大Prompt，而是一个Runtime + OS。

// part 03 · knowledge vs memory

知识层和状态层
各司其职，不要混在一起。

知识层（相对静态）

Resource / Wiki长期知识库、文档、FAQ
Skill可复用能力、工作流模板

状态层（动态变化）

Profile用户偏好、身份、历史
Memory短期工作记忆、对话历史
Working Memory当前任务的中间状态

设计原则：知识层是读多写少，状态层是读写频繁。不要把所有东西都塞进上下文窗口。

这一页是我最想跟大家讲清楚的——知识层和状态层要分开。

知识层：Resource、Wiki、Skill，相对静态，读多写少。

状态层：Profile、Memory、Working Memory，动态变化，读写频繁。

// part 04 · prod harness & eval harness

生产 Harness 和评测 Harness
是同一套设计的两种用法。

✅ 生产 Harness

给用户用的Agent环境
工具是真实API、环境是生产环境
目标：完成用户任务

🧪 评测 Harness

测试Agent用的沙箱环境
工具是Mock API、环境是沙箱
目标：测能力、找边界、收集Trajectory

核心洞察：Trajectory 就是最好的训练数据。

这一页讲生产Harness和评测Harness的关系。

关键洞察：这两者不是分开的，而是同一套设计的两种用法。而且，评测得到的每一条Trajectory都是最好的训练数据。

// part 05 · minimal landing

最小落地建议：
从你已有的技术栈开始。

🧠 记忆层

PostgreSQL + pgvector 存向量索引，Redis存会话状态。

🛠️ 工具层

FastAPI/Express 封装内部API，作为Agent可用工具。

🔄 编排层

LangGraph 或简单状态机，处理 Agent 的思考-行动循环。

好，最后给大家一个最小落地的建议——从你已有的技术栈开始。

记忆层用PostgreSQL + pgvector，工具层用FastAPI/Express，编排层用LangGraph。

// part 06 · common misconceptions

最容易误解的 5 个点。

01
Harness不是大Prompt

它是一套完整的Runtime系统，不是一个巨大的提示词。

02
Agent不是全自动的

需要人工边界、约束和反馈，不是放手不管。

03
Knowledge不是Memory

知识是长期静态的，记忆是短期动态的，要分开管理。

04
不要把所有东西都塞上下文

上下文窗口宝贵，应该只放当前需要的信息。

05
Trajectory很重要

记录完整的决策路径，是改进系统的最佳数据。

好，最后列一下最容易误解的5个点。
